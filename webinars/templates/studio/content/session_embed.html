Before it works

  1. Serve the proxy same-origin. The form only talks to /webinar-api/* on your own site. Your server must route those paths to the first-party proxy (the example in sdk/proxy/server.js, or an equivalent same-origin route in your app).
  2. Create a proxy key. An administrator creates a key with the proxy scope in Studio › API keys. Put it only in the proxy's server-side environment as PROXY_API_KEY, never in the page, GTM or this snippet.
  3. Configure origins. Set PROXY_BACKEND_URL to this platform's origin and PROXY_ALLOWED_ORIGINS to the exact https origin(s) of the pages hosting the form. The proxy issues the __Host-webinar_csrf cookie and checks the X-Webinar-CSRF header, so the page must be served over https on that origin.
  4. Paste the snippet into the page (or a GTM Custom HTML tag) and test a registration.

Full guide: Developers and docs/browser-integration.md.
