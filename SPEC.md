# Webinar Platform — approved scope

Build an Apache-2.0 single-tenant self-hosted Django/PostgreSQL application, one image used for web and durable worker, Compose deployment. Marketing users login via Django admin with administrator/editor/analyst permissions. API consumers use any CMS. External webinar streaming and media URLs only. No SMS delivery; store granular optional SMS consent and withdrawal evidence.

## Core
Event CRUD/revisions; internal name, slug, public title, hero URL, AIDA (attention, interest, decision, action) copy, learning outcomes, hosts/topics, draft/public/unlisted visibility. Explicit recurring series/occurrences with IANA timezone, UTC instants, DST ambiguity validation. Join/waiting links private. Validated thank-you redirect or message. Public upcoming/recorded listing search/topic/host filters. Recording publication. Cancellation/reschedule and attendance/no-show/follow-up events. ICS calendars with stable UID/sequence. Durable registrations before acknowledgement and idempotency conflict detection. Late reminders skipped, cancellation suppresses reminders, reschedule replaces schedules.

## Identity / forms
Canonical camelCase fields email, phone, firstName, lastName, name, company, jobTitle, companySize; common snake_case aliases and explicit per-form mappings. Reject conflicting aliases; no fuzzy guessing. Validate email conservatively, no plus/dot stripping. Phone E.164 only with sufficient country context. Never guess name splits. Blank fields cannot erase existing values. Custom fields namespaced. Versioned schema and field mapping guide.
Server-generated person UUID distinct from occurrence registration and browser session. Email per occurrence deduplication does NOT authorize viewing/updating an existing person's private data. Browser cookie is opaque secret capability, HttpOnly/Secure/SameSite, hashed at rest, revocable; never use public UUID/ad ID/email alone as authentication. New unknown browser cannot hijack existing profile through matching email. Cross-device linking requires verification (or explicitly not supported until verification). Not-you reset and correction UX. Recognition response exposes missing field keys only, no PII. Completion updates only permitted profile on valid capability; registering as someone else must not rebind identity by email. Attribution never authenticates.

## Browser integration — contract shared by workers
Public routes `/api/v1/events`, `/api/v1/events/<slug>`, POST `/api/v1/registrations`.
First-party proxy routes `/webinar-api/profile` GET (query occurrenceId, formVersion), `/webinar-api/registrations` POST, `/webinar-api/reset` POST. Proxy backend forwards to `/api/v1/profile`, `/api/v1/registrations`, `/api/v1/reset` with server-held scoped proxy key; forwards cookies safely and validates exact origin and CSRF. Provide deployable example proxy; no secrets in GTM. Application also supports same-origin direct proxy paths. Profile response `{recognized: boolean, missingFields: string[], formVersion: string}`; no email/name values. POST body `{schemaVersion:'1', occurrenceId, formVersion, idempotencyKey, profile:{...canonical fields}, organization:{externalIds:[{namespace,value}]}, consents:{sms:{granted,disclosureVersion},analytics:{granted},advertising:{granted}}, attribution:{parameters:{},identifiers:{},pageUrl,referrer}, customFields:{}}`. Client consent evidence cannot claim server verification. Response generic thank-you/calendar metadata with no private profile. No private join links in public registration response. Anonymous missing-fields behavior requests full form. GTM script uses data-webinar-form / data-occurrence-id / data-form-version attributes and canonical HTML name attributes. Existing completed fields hidden/disabled, missing fields requested, button 'Confirm my RSVP' when none; no false-success on network failure; accessible errors. Explicit consent integration, no tracking before consent, only allowlisted parameters and available cookies, no fingerprinting. Support Meta, GA4, Google Ads, X, Snap, Reddit cookie IDs conservatively; document availability not guaranteed. URL ValueTrack means populated values only. Strip query/hash from stored page/referrer URL; never harvest whole URLs/cookies. Browser idempotency keys retry same intent, reset after completion.

## Data / integrations
Separate immutable attribution touch table linked to registration/person, first-touch and registration-touch. Namespaced organization external IDs, browser-supplied IDs unverified; verified matching only trusted API. Webhook payload grouped identity/profile/organization/consents/attribution/registration/event/delivery_metadata; versioned and self-contained snapshots with imagery, form version, public copy and trusted delivery links. Destination-level fields/purpose restrictions. Encrypted integration credentials (external env master key), scoped hashed API keys, audit logs without PII/secrets. Signed timestamped webhooks stable delivery IDs, replay-verification example. Transactional outbox, bounded retries/leases, dead-letter/retry UI, SSRF-safe HTTPS allowlist and DNS/IP validation (no redirects, private/metadata targets blocked). Email/CRM generic webhook integrations with mappings; no fabricated native vendors. Retention/deletion command removes PII including queued payloads and attribution. Minimal reporting without inferred attendance from RSVP.

## Deliverables / validation
Source, migrations, tests, JSON Schema/OpenAPI or accurate API reference, GTM script and examples/proxy, Dockerfile dedicated build context, Compose, env example without secrets, secure first-run bootstrap, healthcheck, backup/restore and rollback guide, threat model, Apache license. No default passwords. Non-root image, static assets, production fail-closed settings. No registry push/deployment/real external sends. Verify authorization, CSRF, idempotency/restarts, concurrency, timing/DST, sensitive projections, SSRF, normalization, progressive profiling and consent. State incomplete areas honestly; do not claim production-ready or timed deployment without evidence.

## Worker safety
Only edit assigned workspace files. No commits/pushes, remote mutations, package installs, background processes, Docker/OrbStack, shells or MCP. Pi owns all test/build execution through managed containers. Read/Edit/Write/Grep/Glob only plus bounded Agent delegation when explicitly enabled. Child agents inherit identical scope and safety, use claude-opus-5-5. No agent may broaden tool permissions. Independent workstreams never edit each other's files. Write requested commands to handoff, not execute. Complete implementation first, report tests unrun.
