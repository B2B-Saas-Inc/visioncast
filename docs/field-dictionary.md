# Field dictionary (schemaVersion "1")

The machine-readable source is `docs/registration.schema.json`. Alias and per-form mapping rules are in `docs/field-mapping.md`.

| Key | HTML `name` (SDK) | Notes |
| --- | --- | --- |
| `email` | `email`, `email_address` | Validated conservatively. No plus/dot stripping. The dedupe key is case-folded and never authorises anything. |
| `phone` | `phone`, `phone_number` | Accepted only as E.164, or with the form's default region. The country is never guessed. |
| `firstName` / `lastName` | `firstName`/`first_name`, `lastName`/`last_name` | |
| `name` | `name`, `full_name` | Never split into first and last name. |
| `company` | `company`, `company_name` | |
| `jobTitle` | `jobTitle`, `job_title` | |
| `companySize` | `companySize`, `company_size` | |
| `custom.<key>` | `custom.<key>` | The key must be declared in the form's `custom_fields`. |
| `organization.externalIds[]` | `organization.externalId` + `data-namespace` | Namespace must match `^[a-z0-9][a-z0-9_.-]{0,63}$`. IDs supplied by the browser are always unverified. |
| `consents.sms` | checkbox `consents.sms` + `data-disclosure-version` | A grant needs the current disclosure version and a phone number. |
| `consents.analytics` / `consents.advertising` | from the consent provider | Client claims are stored as evidence and never verified by the server. |
| `idempotencyKey` | generated by the SDK | Must match `^[A-Za-z0-9_\-:.]{8,128}$`. The same intent reuses the key; it resets after a completed registration. |

Additional rules:

- **Blank values:** blank values are omitted by the SDK and ignored by the server, so they never erase stored data.
- **Disabled fields:** fields hidden by progressive profiling are disabled and are not sent.
- **Field error keys:** error keys use the same key names as above. Two forms are specific to errors: `consents.sms.disclosureVersion` and `organization.externalIds.<n>`.
